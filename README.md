# PhantomProxy / Phantom Lab

**Статус проекта:** идёт миграция к поддерживаемому приложению на чистом Go. На текущем этапе рекомендуемый запускной путь это локальная лаборатория симуляций осведомлённости, которая работает только с синтетическими событиями. В репозитории всё ещё присутствуют старые компоненты, поэтому весь проект пока нельзя считать полностью перенесённым на Go.

## Что работает в текущем поддерживаемом контуре

- **Go HTTP-сервер** на стандартной библиотеке `net/http`.
- **Локальная панель** для просмотра событий и состояния лаборатории.
- **Синтетические события:** `visit`, `click`, `training_complete`.
- **Явный allowlist кампаний** и автоматическое истечение срока области тестирования.
- **Аварийная остановка** приёма событий.
- **Ограниченный буфер событий** в памяти, без сохранения после перезапуска.
- **Ограничение размера запроса**, строгая схема JSON и защитные HTTP-заголовки.
- **Go CI:** форматирование, race-тесты, `go vet` и сборка безопасного компонента.

Лаборатория не собирает пароли, cookies, токены сессий, произвольные полезные нагрузки или данные реальных аккаунтов.

## Быстрый старт

Требуется Go **1.24.0 или совместимая более новая версия**.

```bash
git clone https://github.com/rpauts2/phantom-proxy.git
cd phantom-proxy

# Проверить версию Go
go version

# Тесты, vet и сборка поддерживаемой лаборатории
make check

# Запустить лабораторию с явным списком тестовых кампаний
make lab LAB_CAMPAIGNS=demo
```

Панель будет доступна локально: [http://127.0.0.1:8088](http://127.0.0.1:8088).

По умолчанию срок области тестирования составляет 8 часов. Допустимый диапазон: от 1 минуты до 24 часов.

```bash
# Пример с двумя синтетическими кампаниями и сроком 4 часа
make lab LAB_CAMPAIGNS=demo,training SCOPE_DURATION=4h
```

Сервер намеренно отказывается слушать нелокальный IP. Это локальная лаборатория, не развёртывайте её как публичный сервис.

## API лаборатории

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/` | Панель управления |
| `GET` | `/healthz` | Состояние процесса и области тестирования |
| `GET` | `/metrics` | Метрики для Prometheus |
| `GET` | `/api/v1/status` | Состояние, срок действия области, число событий |
| `GET` | `/api/v1/events` | Последние синтетические события в JSON |\n| `GET` | `/api/v1/events.csv` | Выгрузить синтетические события в CSV (лимит 1-500) |
| `POST` | `/api/v1/events` | Добавить разрешённое синтетическое событие |
| `POST` | `/admin/stop` | Аварийно прекратить приём событий |

Для записи события требуются явный заголовок запроса и поля кампании, участника и типа:

```bash
curl -X POST http://127.0.0.1:8088/api/v1/events \
  -H 'Content-Type: application/json' \
  -H 'X-Phantom-Lab-Request: 1' \
  -d '{"campaign_id":"demo","participant_id":"person_01","type":"click"}'
```

Для аварийной остановки:

```bash
curl -X POST http://127.0.0.1:8088/admin/stop \
  -H 'X-Phantom-Lab-Action: stop'
```

Остановка действует до перезапуска процесса. После истечения срока кампании новые события отклоняются. Используйте только вымышленные идентификаторы участников.\n\nВыгрузить последние события в CSV можно по адресу `http://127.0.0.1:8088/api/v1/events.csv?limit=500`.

## Команды разработки

| Команда | Действие |
|---|---|
| `make build` | Собрать Go-бинарник лаборатории |
| `make run` | Собрать и запустить лабораторию |
| `make test` | Запустить race-тесты лаборатории |
| `make lint` | Выполнить `go vet` для поддерживаемого компонента |
| `make fmt` | Форматировать исходники лаборатории |
| `make check` | Форматирование, vet, тесты и сборка |
| `make docker-build` | Собрать минимальный Go-only образ |
| `make legacy-build` | Собрать старую точку входа, только для аудита |
| `make docker-legacy` | Запустить старый многокомпонентный Compose-стек |

Полная проверка всех старых Go-пакетов доступна через `make test-go` и `make lint-go`. Эти команды не являются release gate поддерживаемой лаборатории, пока аудит старых компонентов не завершён.

## Архитектура и план миграции

- `cmd/simulation-lab` — точка входа локальной лаборатории.
- `internal/simulation` — HTTP API, хранилище событий, панель и тесты.
- `Dockerfile.simulation` — минимальный контейнер только с Go-бинарником.
- `docs/GO_ONLY_MIGRATION.md` — этапы миграции и критерии готовности.

Старые API/AI/Celery/Node.js сервисы, прежняя точка входа и Compose-конфигурация пока остаются в репозитории, но **не входят в поддерживаемый Go-only контур**. Их не следует считать проверенными или функционально эквивалентными текущей лаборатории. Переносить или удалять их можно только после инвентаризации и тестов.

Файл `config.yaml` намеренно не изменялся.

## Безопасность

Используйте лабораторию только в рамках согласованных учебных или защитных мероприятий. Поддерживаемый контур предназначен для проверки реакции на симулированные события, а не для сбора учётных данных, обхода средств обнаружения или управления чужими системами.
